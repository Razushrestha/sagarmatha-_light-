▌ System Overview
What you are building and how it all connects
This ERP is a fully integrated business management system for an Electrical & Hardware Shop. It covers every operation from the moment a customer walks in, to VAT billing, stock movement, supplier payments, accounting, and analytics — all in one platform.
🎯  Goal
Replace manual billing, spreadsheets, and disconnected tools with a single professional ERP that is Nepal IRD VAT compliant, supports local payment gateways (eSewa, Khalti, Fonepay), works offline at POS, and scales from one shop to multiple branches.

▌ 1.3  Transaction Architecture (Most Important)
⚡  Core Rule
Every financial event (Sale, Purchase, Return, Payment, Expense, Adjustment) must automatically trigger all downstream effects: stock change, ledger entry, VAT posting, profit update, and audit log — in a single atomic database transaction.
Sale Transaction Flow:
• 1. Create Sale record
• 2. Create Sale Items
• 3. Deduct Stock per item (stock_movements)
• 4. Create Customer Receivable if credit sale
• 5. Post to Sales Account (journal_entry)
• 6. Post VAT to VAT Output Account
• 7. Calculate COGS, update Gross Profit
• 8. Record Payment(s) against sale
• 9. Write Audit Log entry
• 10. Trigger low-stock notification if below threshold
Purchase Transaction Flow:
• 1. Create Purchase record
• 2. Create Purchase Items
• 3. Add Stock per item (stock_movements)
• 4. Create Supplier Payable
• 5. Post to Purchase Account
• 6. Post VAT to VAT Input Account
• 7. Record Payment(s) against purchase
• 8. Write Audit Log entry
🔒  Backend Rule
All permission checks MUST be enforced at the API level. Hiding a button on the frontend is NOT enough. The backend must reject any unauthorized API request regardless of the frontend state.

▌ 2.3  After Login — Role-Directed Landing
Each role goes directly to their workspace after login:
• Sales Staff  →  POS / New Sale screen
• Storekeeper  →  Inventory / Stock screen
• Accountant  →  Accounting / Dashboard
• Admin / Manager  →  Main Dashboard
• Super Admin  →  Main Dashboard + System Settings
▌ 2.4  Security Requirements
• JWT tokens with httpOnly cookies (never localStorage)
• Password hashing with bcrypt (minimum 12 rounds)
• 2FA for Super Admin and Admin (TOTP / Google Authenticator)
• Login history — IP, device, time
• Automatic session logout after inactivity
• Failed login lockout after 5 attempts
• All permission checks enforced at API / backend level
• API rate limiting to prevent brute force
